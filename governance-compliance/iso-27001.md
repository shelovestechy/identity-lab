# ISO/IEC 27001 - Practical View

ISO/IEC 27001 is an international standard for information security management.

It defines requirements for an **ISMS**: Information Security Management System.

In plain words, an ISMS means the organization has a structured way to manage information security.

Not random security tasks.

Not “someone probably knows”.

Not policies that exist only because they look nice in a folder.

ISO/IEC 27001 is not only about IT tools. It is about how the organization manages security through people, processes, responsibilities, risk management, controls, documentation and improvement.

## What ISO/IEC 27001 is for

ISO/IEC 27001 helps an organization protect information in a controlled and repeatable way.

The main idea is risk-based security.

The organization should understand what information it has, what can go wrong, what needs protection and what controls make sense for its own environment.

It does not say that every organization must have the exact same security setup.

That would be too simple and honestly useless.

A hospital, a bank, a small software company and a public sector organization do not have the same risks.

The point is that the organization needs to understand its own risks and manage them properly.

## What it contains

At a high level, ISO/IEC 27001 includes requirements around:

| Area | Plain meaning |
|---|---|
| Organization context | What kind of organization is this and what affects its security? |
| Leadership | Management must take responsibility, not just leave security to IT |
| Risk assessment | The organization needs to identify information security risks |
| Risk treatment | Risks need decisions and controls, not just awareness |
| Objectives | Security work should have clear goals |
| Competence and awareness | People need to know their responsibilities |
| Communication | Security-related information needs to reach the right people |
| Documented information | Important processes and decisions should be written down |
| Operations | Security controls need to work in daily operations |
| Performance evaluation | The organization needs to check if the system works |
| Internal audit | The organization should test its own controls |
| Management review | Leadership should review security performance |
| Continual improvement | Weaknesses should lead to improvement |

The standard also includes **Annex A**, which lists security controls that can be used to treat risks.

In ISO/IEC 27001:2022, Annex A has 93 controls grouped into four themes:

- organizational controls
- people controls
- physical controls
- technological controls

For identity and access work, the most relevant areas are usually access control, identity lifecycle, privileged access, supplier access, logging, monitoring, incident management and evidence.

## What it requires in simple words

ISO/IEC 27001 expects information security to be managed.

That word matters.

Managed means there is structure.

There are responsibilities.

There are risk-based decisions.

There is documentation.

There is review.

There is improvement when something does not work.

Security should not depend only on memory, luck or one person who “just knows how things work”.

That is the difference between having security activity and having a security management system.

## How I connect this to IAM

For my portfolio, ISO/IEC 27001 is not something I want to treat as a separate theory topic.

I use it as a lens for looking at access work.

It helps me ask whether access is actually controlled or only technically possible.

The standard does not need to be repeated on every access page.

The practical connection is this:

| ISO-style thinking | IAM example |
|---|---|
| Risk-based control | Sensitive systems need stronger access checks |
| Clear responsibility | System owners and approvers should be known |
| Documented process | Access requests should leave usable evidence |
| Review and improvement | Access reviews should find and remove bad access |
| Operational control | Joiner, Mover and Leaver processes should work in daily life |
| Management responsibility | Security cannot be only “IT will handle it somehow” |

This is why ISO/IEC 27001 fits well with IAM.

It gives structure to questions that already appear in real access work.

## My practical interpretation

The most useful ISO/IEC 27001 idea for me is the difference between a process existing and a control actually working.

A company can have an access request process.

That does not automatically mean access is well controlled.

A company can have access reviews.

That does not automatically mean wrong access is removed.

A company can have policies.

That does not automatically mean people understand or follow them.

The interesting part is the gap between documentation and reality.

That is where practical IAM work lives.

## What I would check

When looking at access work through an ISO/IEC 27001 lens, I would check:

- are access responsibilities clear?
- are system owners known?
- are access requests documented well enough?
- are privileged rights limited and reviewed?
- are movers checked for old access?
- are leavers handled on time?
- are temporary accesses cleaned up?
- do access reviews include real context?
- can the organization explain why access exists?

This is not about making access work heavy.

It is about making access controlled enough that it can be trusted.
